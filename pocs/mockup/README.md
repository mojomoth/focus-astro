# 웹앱 목업 PoC

요구사항: [docs/POC_MOCKUP.md](../../docs/POC_MOCKUP.md)

데스크톱에서는 `assets/mockup-iphone.png`를 화면 중앙에 표시하고, 목업의 실제 화면 영역에 앱을 배치한다. 모바일에서는 프레임을 제거하고 전체 화면으로 표시한다. 의존성 없이 HTML, CSS, JS만으로 구성했다.

## 실행

```bash
cd pocs/mockup
npm run dev          # http://localhost:5173 (포트 변경: PORT=5180 npm run dev)
npm run dev:https    # https://<LAN IP>:5174, 휴대폰 실기기 확인용 (자체 서명 인증서 자동 생성)
```

- `?frame=1`: 목업 표시를 강제한다. `?frame=0`: 전체 화면을 강제한다.
- 카메라와 마이크는 **보안 컨텍스트(HTTPS 또는 localhost)**에서만 동작한다. 휴대폰에서 LAN IP로 접속할 때는 `dev:https`를 사용한다. 인증서 경고가 뜨면 '계속'을 누른다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `index.html` | 목업 셸과 데모 앱(항해, 권한 점검, 환경). 첫 페인트 전에 표시 모드를 결정한다 |
| `styles.css` | `data-mode="mockup"`과 `data-mode="full"` 레이아웃, 안전 영역 변수, 앱 UI |
| `app.js` | 배율 계산, 터치 제스처, 카메라·마이크 권한 흐름, 환경 정보 표시 |
| `scripts/serve.mjs` | 의존성 없는 정적 서버(HTTP와 HTTPS) |

## 핵심 결정

**목업 배치**
- 원본 851×1848 PNG를 측정한 결과, 투명한 화면 영역은 `x36 y34 780×1782`이고 코너 반경은 약 110px이다.
- 이 값을 1/2 크기의 논리 좌표(프레임 425.5×924, 화면 390×891, 반경 55)로 바꿔 고정 크기로 배치하고, 뷰포트에 맞춰 `transform: scale()`로 축소·확대한다. 그래서 창 크기가 달라도 앱 레이아웃은 항상 390pt 폭의 아이폰 기준으로 유지된다.
- 프레임 이미지는 앱 위에 겹쳐 두고 `pointer-events: none`을 지정한다. 다이내믹 아일랜드가 실제 기기처럼 콘텐츠를 가리고, 터치 입력은 프레임을 통과해 앱에 전달된다.
- 화면 영역은 `clip-path: inset(0 round 55px)`로 둥글게 자른다. 이렇게 하면 transform이 적용된 상태에서도 Safari에서 모서리가 비치지 않는다.
- 목업은 캡션 영역을 뺀 공간의 중앙에 절대 위치로 배치한다. 그리드로 배치하면 축소 전 높이가 레이아웃에 남아 짧은 창에서 목업이 잘린다.

**모드 판별**
- `(hover: none) and (pointer: coarse)` 조건, 즉 입력 장치로 판별한다. 창 너비로는 판별하지 않으므로, 데스크톱 창을 좁혀도 목업이 축소될 뿐 사라지지 않는다.

**안전 영역**
- 모든 여백은 `--sat`, `--sab`, `--sal`, `--sar` 변수를 거쳐 적용한다.
  - 전체 화면 모드: `env(safe-area-inset-*)`. `viewport-fit=cover`가 필요하다.
  - 목업 모드: iPhone 15 Pro 세로 모드 값(상 54, 하 34)으로 흉내 낸다. 가상 상태 표시줄과 홈 인디케이터도 함께 그린다.
- 가로 모드의 좌우 노치는 `--pad-l`과 `--pad-r`(`max(22px, inset + 12px)`)로 피한다.

**터치 인터랙션**
- `touch-action: manipulation`으로 더블탭 줌 지연을 없앤다. `overscroll-behavior: none`으로 당겨서 새로고침과 바운스를 막는다. iOS의 `gesturestart`는 핀치 줌 방지를 위해 막는다.
- 누름 피드백은 `.is-pressed` 클래스를 pointer 이벤트로 직접 붙인다. 터치에서는 `:active`가 늦게 적용되기 때문이다.
- 캐러셀은 제스처 방향이 정해진 뒤에만 포인터를 캡처한다.
  - 첫 번째 손가락만 추적한다.
  - `pointercancel`이나 캡처를 잃으면 선택을 바꾸지 않고 원래 위치로 되돌린다.
  - 플릭은 최소 1칸, 최대 2칸 이동한다.
- 시트는 그립과 제목 영역에서만 끌어 닫을 수 있다. 끄는 거리는 `clientY` 차이를 배율로 나눠 계산한다(목업 배율 보정).
- 목업 모드에서는 커서를 손가락 크기의 원으로 바꾼다. 포인터 좌표는 `toLocal()`에서 배율을 되돌려 계산한다.
- 버튼 최소 높이는 48px로, Apple 권장값 44pt 이상이다. 진동은 Android에서만 동작한다.

**카메라와 마이크**
- 탭(사용자 제스처) 뒤에만 `getUserMedia`를 요청한다. `AudioContext`도 같은 제스처 안에서 생성한다. 그렇지 않으면 iOS에서 suspended 상태로 멈춘다.
- Permissions API로 현재 상태(prompt, granted, denied)를 미리 표시한다. 이 API를 지원하지 않는 브라우저(Firefox의 카메라 권한, 구형 Safari)에서는 '알 수 없음'으로 표시한다.
- 오류 이름별로 안내 문구를 다르게 보여준다.
  - NotAllowed: 권한 거부. iOS와 Chrome의 설정 경로를 각각 안내하고, iframe 안이라면 `allow` 위임이 필요하다고 안내한다.
  - NotFound: 장치 없음.
  - NotReadable: 다른 앱이 장치를 사용 중.
  - Overconstrained: 요청한 조건을 만족하는 장치 없음.
  - Security: 보안 정책으로 차단됨.
- **요청 세대(generation)**: 권한 팝업이 떠 있는 동안 탭을 이동하거나, 앱이 백그라운드로 가거나, 사용자가 장치를 끄면 세대 번호를 올린다. 이후 늦게 도착한 스트림은 즉시 정지한다.
- 시작에 실패하면 트랙, rAF, `AudioContext`를 모두 정리한다.
- 탭 이탈, `visibilitychange: hidden`, `pagehide` 시점에 모든 장치를 정지한다. 이렇게 해야 카메라 표시등이 꺼지고 iOS의 인터럽트에도 대비할 수 있다.
- 카메라 전환은 다음 `deviceId`를 명시해 요청한다. 방향 정보가 없는 웹캠 두 대에서도 동작한다. iOS는 카메라를 동시에 두 대 열 수 없으므로, 기존 카메라를 정지한 뒤 다시 요청한다.
- `video`에는 `playsinline muted autoplay` 속성을 지정한다. 전면 카메라 화면은 좌우를 반전해 거울처럼 보이게 한다.

## 미검증

- 실제 iOS Safari와 Android Chrome 기기에서의 안전 영역 값, 권한 팝업, 카메라 전환. Chromium 에뮬레이션은 safe-area inset을 0으로 처리하므로 실기기에서 확인해야 한다.
- 홈 화면에 추가한 standalone 모드(PWA)에서의 권한 동작.
